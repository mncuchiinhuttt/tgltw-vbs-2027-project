01 / system

A retrieval system shaped by the live room.

The default path is intentionally bounded. Expensive precision steps remain available, but only when the operator decides the extra latency is worth it.

01

Build evidence offline.

Keyframes, speech, OCR, metadata, ambient audio, and provenance are prepared before the task arrives.

V3C / MVK / GYNSURG
02

Search the fast path first.

Dense and payload full-text retrieval meet in reciprocal-rank fusion, with temporal coherence and scene diversification keeping the result grid useful.

densesparseRRF
03

Answer only on real media.

Grounded VQA preserves candidate, video, frame, and timestamp identity. Missing evidence fails closed instead of becoming a confident guess.

GROUNDING CONTRACT / ON

02 / task map

Five doors into the same evidence graph.

Each mode gets its own interaction contract; the shared result still resolves to media an operator can inspect.

KIS-Vvisual known-item

Show the system what you saw.

A short visual clip is sampled, embedded, searched, merged, and returned with source identity attached.

clip→frames→hits
KIS-Ttext known-item

Translate memory into a target.

CQR, HyDE, dense/sparse retrieval, RRF, and bounded reranking search for one known segment.

text→fusion→target
KIS-Cconversational

Ask one better question.

Clarification and feedback update a bounded session instead of launching an unbounded agent loop.

query→clarify→focus
AVSad-hoc search

Find breadth without spam.

Scene diversification and manual browsing favor useful shots from distinct source videos.

concept→diversify→submit
VQAgrounded answer

Answer from the frame you can prove.

Candidate resolution, real media loading, strict JSON, and evidence parity keep the answer auditable.

question→frame→answer

03 / evaluation

Two tracks. One honest claim.

Official DRES outcomes and offline replay diagnostics answer different questions. We keep them separate.

ALIVE DRES

What happened in the room?

  • Official score and rank per task/session
  • Time-to-first and time-to-correct
  • Correct / false submissions and judge outcomes
  • Ordered query, clarification, and interaction trace

BOFFLINE REPLAY

What did the engine contribute?

  • Frozen manifest, index, model, and config
  • Recall@K, MRR, nDCG, hit rate
  • VQA grounding and evidence parity
  • Warm/cold p50 and p95 latency
